# Repository tooling

Where the tools are, which checks to run, and the test rigs that exist. Last updated 2026-09-03.

Updated 2026-09-04: the bootstrap no longer explicitly manages host daemon startup, and the Docker
test requires an already reachable daemon. Image builds set `LAB_IMAGE_BUILD=1` because BuildKit
may expose neither runtime container markers nor useful cgroup paths for detection.

## What happened

- `deno` is installed at `/root/.deno/bin/deno` and is not on `PATH` for non-login shells.
  Every `deno task ...` must run from `curriculum-tools/`.
- `deno task check` runs `fmt --check` over the whole engine, so one unformatted file in any
  course fails the check for everyone. During the Linux course build this made another
  session's `deno task check` fail for hours.
- `deno fmt` has `lineWidth: 100` and also rewraps Markdown (`PLAN.md`, `SKILL.md`). Hand-wrapped
  80-column prose will be rewritten on the next `fmt`, which produces large, noisy diffs.
- `courses/*/lessons.json` is excluded from `fmt`; it is generated by `deno task build <course>`
  and is committed.
- Docker tests require a reachable daemon (`docker info`); `scripts/docker/test.sh` builds
  the lab image with `scripts/lab-setup.sh` and runs `scripts/docker/verify.sh` (38 tool checks
  as of 2026-09-03). An earlier note claiming "no startable daemon" was wrong.
- Two lab-setup packages were missing until the Linux review: `time` (GNU `/usr/bin/time`) and
  `e2fsprogs` (`mkfs.ext4`), plus `python3` and `sudo`. `verify.sh` now checks all four.

## Why it matters

Running the wrong check wastes a validation cycle, and formatter churn hides real changes in a
diff. The Docker path is the only way to prove `lab-setup.sh` works on a fresh machine.

## How to apply

- Scoped checks while a course is in flux (replace `linux` with your course):

  ```sh
  cd /root/Software/skills-tools/curriculum-tools
  export PATH=/root/.deno/bin:$PATH
  deno fmt courses/linux/curriculum courses/linux/PLAN.md courses/linux/skill
  deno fmt --check courses/linux/curriculum src tools
  deno lint courses/linux/curriculum src
  deno check courses/linux/curriculum/*.ts src/*.ts tools/*.ts
  deno task test
  ```

  Run the full `deno task check` before pushing so the repo stays green for everyone.
- Run `deno fmt` on Markdown you edit under `curriculum-tools/` before committing, so the
  reformat lands in your commit rather than someone else's.
- Non-root test rig (used to validate the Linux course's privileged lessons as a sudo user):

  ```sh
  useradd -m linuxtutor
  echo 'linuxtutor ALL=(ALL) NOPASSWD: ALL' > /etc/sudoers.d/linuxtutor
  cp -r /root/Software/skills-tools/curriculum-tools /home/linuxtutor/ct
  mkdir -p /home/linuxtutor/bin && cp /root/.deno/bin/deno /home/linuxtutor/bin/
  chown -R linuxtutor: /home/linuxtutor
  su - linuxtutor -c 'cd ~/ct && ~/bin/deno run -A tools/validate.ts linux 34'
  ```

  Copy the freshly built `lessons.json` into the copy before each run. Remove the rig when done:
  `userdel -r linuxtutor; rm -f /etc/sudoers.d/linuxtutor`.
