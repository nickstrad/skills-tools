# Batch five: explain query work before choosing a remedy

Primary design, 2026-09-10. Lesson 15 is already available; the requested batch is **16–21**. Follow
the fixed PLAN.md titles and slugs. Each lesson is one 20–30 minute comparison in one psql session,
with concepts and a terminal diagram before commands, a substantive evidence review, and one
optional, independently runnable variation. No learner scripts or extra reading are required.

## Experiments and acceptance

16. `read-a-plan-as-evidence`: create a small deterministic heap with no index; run EXPLAIN first,
    then EXPLAIN (ANALYZE, BUFFERS, TIMING OFF) for the same filtered SELECT. Identify estimated
    rows versus actual output rows, rows removed, loops, and buffer accesses. A second execution may
    warm buffers but is not a disk benchmark. Include aggregate parent versus scan child to
    distinguish the one result row from scanned work. Variation changes predicate selectivity.
17. `statistics-and-estimates`: analyze a deterministic two-value distribution, then change it
    substantially with UPDATE while table autovacuum is disabled. Measure the same predicate before
    and after explicit ANALYZE without changing data between those two plans. Stale estimate must
    differ materially from actual rows; refreshed estimate approaches actual. Explain sampling,
    most-common-value frequency, and why ANALYZE does not build an index or reclaim dead versions.
    Variation reverses the skew and repeats the information repair.
18. `index-crossover`: same analyzed indexed table, narrow and broad ranges selecting heap payload.
    Observe index access for narrow and sequential scan for broad without disabling scan types.
    Table size/row width and local cost controls may stabilize the fixture, but explain each
    control; do not promise a universal percentage. Optional medium selectivity need not pick a
    fixed node.
19. `composite-index-order`: one tenant's newest limited rows from a deterministic multi-tenant
    event table. Compare (event_time, tenant_id) with (tenant_id, event_time), one index at a time,
    for the identical WHERE tenant_id = ... ORDER BY event_time ... LIMIT workload. Use a stable
    unique ordering value so tie behavior does not distract. Show scan work/buffers, matching rows,
    and sort presence/absence where observed. Both orders can supply ordered data; do not falsely
    promise that the first always sorts. Variation reverses sort direction and observes backward
    scan.
20. `index-only-needs-visibility`: a selective query with all required columns in a covering B-tree.
    VACUUM baseline, committed update of qualifying rows, same plan, VACUUM, same plan again.
    Require Index Only Scan in all compared phases, zero / positive / zero Heap Fetches. Disable
    autovacuum only on this fixture. Explain visibility map's page granularity and why coverage does
    not remove MVCC checks. Variation omits a projected column from coverage and observes heap
    access.
21. `sort-spill`: modest deterministic payload table and full ORDER BY without LIMIT or matching
    index. Separate BEGIN/SET LOCAL work_mem/EXPLAIN/COMMIT blocks at 64kB and a bounded larger
    budget (e.g. 32MB). Require external merge + temporary I/O versus quicksort + no temp I/O, same
    actual row count. Disable parallel query locally for one visible consumer. Explain per-sort,
    per-worker and concurrent-query memory, instrumentation overhead, and no global tuning claim.
    Variation uses a bounded LIMIT and distinguishes top-N sorting from sorting all input rows.
