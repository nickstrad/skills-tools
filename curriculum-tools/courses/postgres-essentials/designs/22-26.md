## 22 — join-memory

Owned module: curriculum/17-join-memory.ts (JOIN_MEMORY and JOIN_MEMORY_VISUAL).
Prerequisite sort-spill. One psql session, named pe_join_* tables. Compare the same hash join over
bounded generated inputs with 64kB versus 16MB work_mem; hold hash_mem_multiplier=1 and disable
parallelism locally. If necessary disable alternative join methods locally and explain that this
isolates the mechanism, not a planner recommendation. Observe equal actual join rows, Hash Batches
>1 with temporary traffic versus Batches=1 without it. Explain build/probe, per-operation allowance,
and multiplicative concurrent demand; do not call work_mem a process cap. Optional variation changes
only hash_mem_multiplier at the small work_mem and explains its effect on the hash allowance.
Author validates exact source SQL and displayed variation in an owned disposable cluster.

## 23 — commit-and-wal

Owned module: curriculum/18-wal.ts (WAL, COMMIT_WAL_VISUAL, WAL_PER_WRITE_VISUAL), together with 24.
Prerequisite join-memory. One psql session; named pe_commit_wal table. Show fsync, synchronous_commit,
insert/write/flush LSN meanings. Capture an insert LSN after a logged write inside a transaction,
commit with SET LOCAL synchronous_commit=on and show flush >= saved pre-commit write position.
Explain this measured lower bound is not an exact commit-record LSN. Contrast a local off commit;
show returned row and positions without requiring a race-dependent unflushed gap. Document that
on waits for local commit WAL flush in this standalone configuration with fsync on, off permits
acknowledgement before flush; no claim that this observation proves power-loss durability. A rollback
variation demonstrates that WAL bytes do not imply committed visible effects. Bounded settings,
cleanup, primary PostgreSQL 16 documentation citations in acceptance/design.

## 24 — wal-per-useful-write

Prerequisite commit-and-wal. Same owned module as 23. Compare equal rows/payload and individual INSERT
statements, 200 autocommit transactions versus 200 statements inside one transaction, so batching is
the changed factor. Capture pg_current_wal_insert_lsn around work; report interval bytes, bytes per
useful row, equal row counts/checksum and transaction counts. Avoid EXPLAIN WAL alone because it
excludes the COMMIT record. Explain cluster-wide contamination and full-page-image/checkpoint effects;
control fixture conditions and validate on a quiet private cluster. Do not assert universal speedup
or exact per-row production costs. Optional intermediate batch size, fully runnable.

## 25 — checkpoint-writeback

Owned module curriculum/19-checkpoint.ts (CHECKPOINT_WRITEBACK and CHECKPOINT_VISUAL), supplied
lab/checkpoint.py. Prerequisite wal-per-useful-write. One shell terminal runs a supplied controller
which allocates its own unique /tmp/pe-checkpoint-* PostgreSQL 16 cluster, never accepts a target
cluster/path. It holds an UPDATE transaction open, shows own value vs another connection, counts
relation-specific dirty buffers with pg_buffercache, issues CHECKPOINT from another connection,
then observes reduced dirty buffers and still-open transaction with unchanged external visibility.
Roll back and show original committed value. Background writer disabled only on this private fixture;
small buffers/data and long automatic checkpoint interval keep observation bounded. Optional commit
instead of rollback establishes independent decision. Budget <200MB and normal stop/remove in finally,
including Ctrl-C. Helper supports root through runuser and normal users directly; use pg_config bindir.
A local helper may be self-contained to keep ownership disjoint from primary crash implementation.

## 26 — crash-replay (primary implementation)

Owned module curriculum/20-crash-replay.ts (CRASH_REPLAY and CRASH_REPLAY_VISUAL), lab/crash.py.
Prerequisite checkpoint-writeback. Supplied controller creates a unique private cluster with durable
settings, checkpoints baseline, commits one update, explicitly aborts another and leaves a third
open in a persistent connection. Establish post-checkpoint WAL progress and pre-crash committed
inventory. pg_ctl stop -m immediate on this exact owned cluster, restart, read recovery log lines
and independent rows. Committed survives; aborted and interrupted changes do not appear. Include
an optional clean-shutdown comparison. Assert actual interrupted recovery/redo log, not just final
rows. This is PostgreSQL process failure with host/storage alive; never simulate corruption or power
failure. Cleanup always stops and removes owned fixture, no user-supplied path or learner endpoint.
